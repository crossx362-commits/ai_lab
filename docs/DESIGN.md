## 1. 무슨 게임인가

유니티 2D 쿼터뷰 **뱀서라이크 + 파티 RPG**. 픽셀아트.

경쟁 포지션: **가챠·스태미나·일일 숙제 없이, 죽으면 사라지는 5인 파티를 직접 살려
탑을 오르는 자동전투 RPG.** 잡몹은 준비와 관찰, 보스는 이동·스킬·긴급 탈출로 직접 개입한다.

한 문장: **죽으면 캐릭터가 진짜 사라지는 게임.** 캐릭터마다 목숨 3회, 3번 죽으면
캐릭터와 장착 장비가 영구 삭제된다. 환생석은 캐릭터만 Lv1로 되돌리고 장비는 복구하지 않는다. 이 영구성이 모든 설계의 뿌리다 —
파티 편성도, 전직도, 탑 등반도 "잃을 수 있으니까" 무게가 생긴다.

- 프로젝트: `projects/ashes-to-stars/` · 유니티 6000.3.14f1 · 빌트인 렌더 파이프라인
- 아트: **힉스필드로 생성하는 2D 픽셀아트 확정**. 생성 원본을 배경 제거·프레임 분리·바닥 정렬한 뒤
  Unity `Resources`에 Point 필터로 반입한다. 전 유닛은 **1방향 원본 + 좌우 `flipX`**, 캐릭터 13프레임·몬스터 22프레임 계약을 쓴다. 블렌더 결과물은 기존 플레이스홀더 비교용으로만 유지한다
- 캐릭터 뽑기·가챠 **없음**. 기본 4직업을 키워서 전직시킨다
- 전직 경로: **기본직업 5종(탱·물리딜·마법딜·힐·버퍼) → Lv20 1차 11종 → Lv50 같은 직업 2차 각성**.
  오너 21:38이 시작 직업을 4종에서 5종으로 갈랐다. 마법딜은 마법사 아트를 쓰고, 1차는 마법사·소환사다.
  프로토타입의 기존 1차 직업 저장은 1차 완료로 보존하고, 새 캐릭터부터 기본직업으로 만든다
- 시작은 1명을 고르고 5~10분에 두 번째를 영입해 **시작 로스터 2명**을 완성한다. 첫 레이드 전
  무료 영입 3회로 5인을 만들며, 이후 본성 명부에서 종족·기본직업을 직접 골라 영입한다
- **생존 보유 캐릭터가 0명일 때만** Lv1 무장비 긴급 영입 1명을 무료 지급한다. 회복·수비·스케줄 중인 캐릭터는 생존으로 세며 구조 캐릭터는 동시에 1명만 활성화한다

## 2. 핵심 루프 — 탑 등반 풀 루프

```
영지(허브)
  └→ 필드 자동사냥(뱀서) ──→ 재화·경험치
       └→ 성장 · 전직(기본4 → 1차11 → 2차11) · 합성
            └→ 던전 노드 맵 ──→ 노드 전투 ──→ 보상
                 └→ 탑 등반(최대 100층)
                      └→ 5층마다 레이드 보스(총 20회) ← 명확한 벽
                           └→ 환생석·전직 증표 ──→ 다시 성장으로
```

**이 루프가 끊기는 지점이 곧 다음 할 일이다.** 지금 어디서 끊겨 있는지는 `STATUS.md`.

## 3. "이 정도면 됐다" — 완료 판정

**기획서의 ✅ 확정 항목이 전부 코드에서 실측 성립할 때.**

기계가 판정할 수 있어야 루프가 스스로 멈춘다. 그래서 각 ✅는 다음 셋을 갖춰야 완료다:

1. **통과 기준이 수치나 화면으로 표현될 것** — "잘 된다"는 완료가 아니다
2. **네거티브 컨트롤** — 되돌리면 다시 깨지는지 확인. 이게 없으면 우연히 통과한 것과 구분이 안 된다
3. **증거가 파일로 남을 것** — CSV·스크린샷·로그. 다음 세션이 재검증 없이 믿을 수 있게

## 4. 매 이터레이션이 지켜야 할 것

1. **`INBOX.md` → `STATUS.md` → 이 파일** 순으로 읽는다. INBOX가 최우선이다
2. 한 번에 **한 항목**만 잡는다. 통과 기준·네거티브 컨트롤까지 끝내야 완료다
3. 프로토타입은 **V2 조작감 → V3 보스 완주 → V4 영구 삭제 수용성** 순서다.
   오너가 연라고 한 로컬 경매·침략만 예외다. 온라인 서버·영지 확장은 열지 않는다.
4. **화면은 화면으로 확인한다** — `tools/qa_shot.sh`로 직접 보고 판단한다.
   이 프로젝트는 "500체 700fps PASS"를 낸 화면이 **텅 비어 있던** 전례가 있다
   레벨업·전직·보스·사망·결과는 각각 §16-9의 지정 순간을 PNG로 남겨야 완료다
   새 힉스필드 생성 전에는 `projects/ashes-to-stars/art/ARTIFACT_INDEX.md`에서 원본·반입물·소비처와
   `higgsfield generate list`의 대기 작업을 확인한다. 이미 있거나 생성 중인 항목은 다시 요청하지 않는다
5. 끝나면 **`STATUS.md`를 인수인계서처럼** 갱신한다. 다음 세션은 기억이 없다
6. 커밋은 고친 파일만 지정해서 add하고 곧바로 commit — 자동화 크론도 master에 직접 커밋한다
