## 1. 무슨 게임인가

유니티 2D 쿼터뷰 **뱀서라이크 + 파티 RPG**. 픽셀아트.

한 문장: **죽으면 캐릭터가 진짜 사라지는 게임.** 캐릭터마다 목숨 3회, 3번 죽으면
장비까지 영구 삭제된다(환생석으로만 복구). 이 영구성이 모든 설계의 뿌리다 —
파티 편성도, 전직도, 탑 등반도 "잃을 수 있으니까" 무게가 생긴다.

- 프로젝트: `projects/ashes-to-stars/` · 유니티 6000.3.14f1 · 빌트인 렌더 파이프라인
- 아트: **픽셀아트 확정**(오너 기준 시트 3종, `GAME_ART_RESOURCES.md` §0-A)
- 캐릭터 뽑기·가챠 **없음**. 기본 4직업을 키워서 전직시킨다

## 2. 핵심 루프 — 탑 등반 풀 루프

```
영지(허브)
  └→ 필드 자동사냥(뱀서) ──→ 재화·경험치
       └→ 성장 · 전직(기본4 → 1차11 → 2차11) · 합성
            └→ 던전 노드 맵 ──→ 노드 전투 ──→ 보상
                 └→ 탑 등반(최대 100층)
                      └→ 5층마다 레이드 보스(총 20회) ← 명확한 벽
                           └→ 환생석·전직 증표 ──→ 다시 성장으로
```

**이 루프가 끊기는 지점이 곧 다음 할 일이다.** 지금 어디서 끊겨 있는지는 `STATUS.md`.

## 3. "이 정도면 됐다" — 완료 판정

**기획서의 ✅ 확정 항목이 전부 코드에서 실측 성립할 때.**

기계가 판정할 수 있어야 루프가 스스로 멈춘다. 그래서 각 ✅는 다음 셋을 갖춰야 완료다:

1. **통과 기준이 수치나 화면으로 표현될 것** — "잘 된다"는 완료가 아니다
2. **네거티브 컨트롤** — 되돌리면 다시 깨지는지 확인. 이게 없으면 우연히 통과한 것과 구분이 안 된다
3. **증거가 파일로 남을 것** — CSV·스크린샷·로그. 다음 세션이 재검증 없이 믿을 수 있게

### 판정 예시 (이미 통과한 것)

| ✅ 항목 | 통과 기준 | 실측 |
|---|---|---|
| §9 레이드 1인 불가 | 1인 구성이 5인 대비 현저히 짧게 생존 | **C/A = 0.08** (5회 중앙값) |
| §10-4 도발이 저격을 끊는다 | 도발 OFF가 눈에 띄게 나빠질 것 | **D/A = 0.66** (목표 0.75 이하) |
| §3 전투 스타일이 데이터에서 온다 | 런타임 소비처 ≥1 | `W3Party.cs:52` `Resources.LoadAll` |

### 아직 안 된 것의 예

- §10-5 보스 기믹 3종 중 **쫄 소환이 빈 GameObject**(`BossBattle.cs:317`)
- §3 종족 4종이 전투에 **영향 0**(`RaceDef` 소비처 없음)
- §16 영지 하위 건물 4종이 **전부 "아직 내용이 없다"**(`EstateScreen.cs`)
- §10-9 잡몹 상한이 코드에 **200**(기획서는 300~500)

## 4. 매 이터레이션이 지켜야 할 것

1. **`INBOX.md` → `STATUS.md` → 이 파일** 순으로 읽는다. INBOX가 최우선이다
2. 한 번에 **한 항목**만 잡는다. 통과 기준·네거티브 컨트롤까지 끝내야 완료다
3. **화면은 화면으로 확인한다** — `tools/qa_shot.sh`로 직접 보고 판단한다.
   이 프로젝트는 "500체 700fps PASS"를 낸 화면이 **텅 비어 있던** 전례가 있다
4. 끝나면 **`STATUS.md`를 인수인계서처럼** 갱신한다. 다음 세션은 기억이 없다
5. 커밋은 고친 파일만 지정해서 add하고 곧바로 commit — 자동화 크론도 master에 직접 커밋한다
