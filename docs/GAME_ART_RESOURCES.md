## 0-A. ✅ 아트 방향 확정 — 픽셀아트 (오너 기준 시트 제시 2026-08-13)

> 오너가 **기본형 스프라이트 시트**를 제시했다. 이것이 이 게임의 아트 기준이며, 아래 모든 산정은 여기에 맞춘다.

### 기준 시트가 정한 것

| 항목 | 확정 내용 |
|---|---|
| **스타일** | **픽셀아트** (하이라이트·아웃라인이 있는 정교한 도트, 어두운 배경 대비) |
| **기본 계열 4종** | 기본 탱(방패+검) / 기본 딜(한 손 무기) / 기본 힐(지팡이·성구) / 기본 버퍼(악기·두루마리) |
| **애니메이션 상태 6종** | 대기 · 이동 · 공격 · **특수(도발/회피/캐스팅/오라/제스처)** · 피격 · 사망 |
| **프레임** | 상태당 **3~4프레임** |
| **색 팔레트** | 탱=청/금 · 딜=흑/자주 · 힐=백/금·초록 · 버퍼=녹/금 |

- 기획서 §3의 **기본 4계열(탱·딜·힐·버퍼)** 과 정확히 대응한다 — 첫 시작 2캐릭(§3)도 이 넷 중에서 고른다
- 특수 상태를 한 칸에 묶은 것이 중요하다: **도발·회피·캐스팅·오라·제스처가 직업마다 다른 의미로 같은 슬롯을 쓴다** → 상태 수를 늘리지 않고 직업 개성을 낸다

### 기준 시트 ② — 이동기 (오너 제시 2026-08-13)

| 직업군 | 이동기 형태 | 프레임 | 무적 표시 색 |
|---|---|---|---|
| **탱** | 방패 돌진 | 5~8 (돌진 → 방패 충격 섬광 → 정지) | **금색 구체** |
| **근접 딜** | 구르기 | 5~8 (몸을 말아 회전) | **보라 오라** |
| **원거리 딜** | 점멸/백스텝 | 5~8 (잔상 → 사라짐 → 재출현) | **청록 궤적** |
| **힐·버퍼** | 짧은 스텝 | 5~8 (가볍게 미끄러짐) | **금+초록 링** |

- 기획서 §5의 직업별 이동기 변주와 **정확히 대응한다**(탱=방패 돌진 / 근접=구르기 / 원거리=점멸·백스텝 / 지원=짧은 스텝)
- **이동기는 기본 모션보다 프레임이 많다(3~4 → 5~8)**. 타당하다 — §5에서 "무적 프레임이 이 게임 조작의 핵심 기술"이라고 정한 이상, 회피 동작이 가장 잘 읽혀야 한다
- ⭐ **무적 표시가 별도 이펙트로 있는 것이 가장 중요하다.** §5는 "무적 0.3초를 정확히 쓰면 한 번 산다"를 조작의 핵심으로 삼았는데, **무적 상태가 눈에 안 보이면 그 기술은 학습이 불가능하다.** 직업군마다 색이 달라 파티 전투에서 누가 무적인지도 구분된다
- ⚠️ **빠진 것: 소환사의 "위치 교체"**(§5 표에 있음 — 소환수와 자리를 바꾸는 이동기). 시트에 없으므로 별도 제작 필요

### 기준 시트 ③ — 캐릭터 디자인 확정본 (오너 제시 2026-08-13)

4직업군의 **최종 디자인과 아이콘**. 앞으로 모든 캐릭터 아트는 이 실루엣·색을 기준으로 파생시킨다.

| 직업군 | 아이콘 | 실루엣 특징 | 주 색 | 장비 |
|---|---|---|---|---|
| **탱커** | 방패 | 중장갑, 투구에 **청색 깃털**, 어깨 판금이 크다 | 청·은·금 | **대형 방패(별 문양) + 철퇴** |
| **딜러** | 교차 검 | 날렵함, **자주색 망토 + 목 스카프**, 흑발 | 흑·자주 | 한 손 검 |
| **힐러** | 십자 지팡이 | **흰 후드 + 금 테두리**, 로브 안감 초록 | 백·금·초록 | 녹색 보석 지팡이 |
| **버퍼** | 사각 별 | **녹색 마녀모자**, 손끝에 반짝임 이펙트 | 녹·금 | 녹색 보석 지팡이 |

- **아이콘 4종이 함께 확정**됐다 — UI(파티 편성·전투 스타일·랭킹)에서 직업군을 나타내는 기호로 그대로 쓴다
- 실루엣이 서로 확실히 구분된다: 탱커=넓고 각짐 / 딜러=좁고 날카로움 / 힐러=둥근 후드 / 버퍼=뾰족한 모자. **화면에 수백 마리가 나오는 게임에서 실루엣 구분은 색보다 중요하다** — 이 기준을 종족 팔레트 스왑에도 유지할 것(§0-B 규칙 2)

#### ⚠️ 시트 ①과 다른 점 두 가지 — 확인 필요

| 항목 | 기준 시트 ①(모션) | 기준 시트 ③(디자인 확정본) |
|---|---|---|
| 탱커 무기 | 방패 + **검** | 방패 + **철퇴** |
| 버퍼 | **악기(류트)/두루마리** — 음유시인 | **지팡이 + 마녀모자** — 마법사풍 |

- 디자인이 갱신된 것인지, 같은 직업군의 다른 변형인지 판단이 필요하다
- 기획서 §3의 버퍼 1차 전직은 **음유시인·주술사·정령사** 3종이다. 시트 ③의 버퍼는 셋 중 **정령사/주술사** 쪽에 가깝고, 시트 ①의 악기는 **음유시인**이다 → **둘 다 맞을 수 있다**(같은 버퍼 계열의 다른 전직). 그렇다면 기본형 버퍼의 표준 외형이 무엇인지만 정하면 된다
- 탱커 무기도 마찬가지로 **수호기사=검+방패 / 광전사=철퇴** 로 갈리는 것일 수 있다

### 📥 현재 스프라이트 반입 규격

현재 힉스필드 생성본은 직업별 13프레임, 몬스터 행동형별 22프레임을 후처리해 런타임에 반입했다. 방향 추가가 필요하면 이미 확정된 실루엣을 참조 이미지로 넣어 같은 캐릭터의 방향 시트를 만든다. 기존 캐릭터를 새 디자인으로 다시 생성하지 않는다.

| 항목 | 규격 |
|---|---|
| 폴더 | `unity/Assets/Resources/sprites/<직업군>/` |
| 파일명 | `<직업군>_<상태>_<프레임번호>.png` 예: `tank_walk_00.png` |
| 현재 상태 | 캐릭터 `idle/walk/attack/special/hurt/death/dash/invuln`, 몬스터 `idle/walk/attack/hurt/death` |
| 방향 확장 | `S`(정면) · `N`(후면) · `E`(측면), W는 E를 좌우 미러. 기존 13/22프레임 계약을 깨지 않는 별도 확장으로 진행 |
| 피벗 | 하단 중앙 (발밑) — 쿼터뷰 Y정렬이 발 기준이라 이게 어긋나면 캐릭터가 땅에 안 붙는다 |
| 여백 | 프레임마다 캔버스 크기를 같게 — 다르면 애니메이션이 떨린다 |

- 유니티 임포트 설정은 자동화돼 있다(`Assets/Editor/TextureImportRules.cs`). 2026-08-16 반입물 메타 실측은 `filterMode: 0`(Point)·기본 플랫폼 `textureCompression: 0`이다

### ✅ 제작 파이프라인 — 힉스필드 2D

지금까지 §0-B·§3은 "블렌더로 3D를 만들어 2D로 렌더한다"를 전제로 물량을 산정했다. **픽셀아트는 그 방식으로 못 만든다** — 3D 렌더를 다운스케일하면 도트가 뭉개져 이 시트 같은 선명함이 안 나온다.

| 용도 | 기존 계획 | **수정** |
|---|---|---|
| 캐릭터·몬스터·보스 | 블렌더 3D 렌더 | **힉스필드 2D 생성 → 배경 제거 → 프레임 분리·정렬** |
| 프로토타입 플레이스홀더 | 블렌더 3D 렌더 | **기존 비교본만 유지**, 새 최종 아트에는 사용하지 않음 |
| 바닥·배경·건물 | 블렌더 렌더 | **힉스필드 2D 단일 이미지 생성 → 화면 비율·투명도 후처리** |
| 이펙트 | 블렌더 렌더 | **힉스필드 2D 심볼 1장 + 코드 크기·회전·투명도 애니메이션** |

- 생성 요청 전에 `ARTIFACT_INDEX.md`의 중복 생성 방지 게이트를 통과해야 한다. 이미 원본·반입물·대기 작업 중 하나라도 있으면 다시 요청하지 않는다

## 0-B. ✅ 최소화 방침 (오너 지시 2026-08-13) — **이 절이 아래 §1~6보다 우선한다**

> 아래 §1~6은 "제대로 만들면 얼마나 드는가"를 산정한 것이다(3,400~3,950장).
> 오너 지시는 **스프라이트 최소화**이므로, 실제 제작은 이 절의 규칙을 따른다.

### 핵심 전환: 세어야 할 것은 "장수"가 아니라 **고유 디자인과 생성 요청 수**

같은 대상을 여러 세션이 다시 생성하면 크레딧과 검수 시간이 동시에 낭비된다. 비용 단위는 PNG 장수가 아니라 **확정된 실루엣·스타일 앵커·힉스필드 요청 1회**다. 한 번 확정된 원본은 후속 방향·상태 생성의 참조 이미지로 재사용한다.

| | 기존 산정 | **최소화 방침** |
|---|---|---|
| 고유 디자인 앵커 | (미산정) | 기본직업 4 · 몬스터 행동형 4 · 보스 실루엣 4 · 공용 이펙트 8 |
| 스프라이트 장수 | 3,400~3,950 | **약 830** |
| 제작 방식 | 3D+2D 혼합 | **힉스필드 2D 생성 + 자동 후처리** |

### 적용 규칙 5가지 (어기면 물량이 즉시 몇 배가 된다)

1. **방향은 최대 4방향만 만들고 좌우 미러링으로 8방향을 만든다.** 쿼터뷰는 좌우 대칭이라 이게 통한다 — 장수 절반
2. **종족 4종은 스프라이트를 추가하지 않는다.** 실루엣을 바꾸지 말고 **런타임 팔레트 셰이더**로 색만 바꾼다. 종족 차이는 색·이펙트·UI 아이콘으로만 표현 → 추가 0장
3. **몬스터 계열 5종도 색조로만 구분한다.** AI 4종의 실루엣만 만들고 계열은 `MobDef.색조`로 처리(이미 그렇게 구현돼 있다) → 20종이 실루엣 4개
4. **정예 6유형은 색 + 크기 + 오라 이펙트로만 구분한다.** 별도 모델 없음 → 추가 0장
5. ~~애니메이션 3상태 고정~~ → **기준 시트대로 6상태 × 3~4프레임**(§0-A). 피격·사망을 코드로 대체하려 했으나 오너 시트에 전용 프레임이 있으므로 그대로 따른다 — 대신 **특수 상태 슬롯 1칸을 직업별로 다른 의미로 재사용**해 상태 수를 더 늘리지 않는다

### 2-1. 캐릭터 스프라이트

**전략: 기본형 + 팔레트 스왑 + 직업별 파츠 교체**

#### 기본 캐릭터 모양

| 기본형 | 실루엣 설명 | 8방향 필요? | 애니메이션 상태 |
|------|----------|-----------|----------------|
| **기본 탱** | 방패+검, 넓은 어깨 | ✅ | 대기·이동·공격·도발·피격·사망 |
| **기본 딜** | 한 손 무기 중심, 날렵한 자세 | ✅ | 대기·이동·공격·회피·연격·피격·사망 |
| **기본 힐** | 지팡이/성구, 양손 자세 | ✅ | 대기·이동·공격·캐스팅·피격·사망 |
| **기본 버퍼** | 악기/두루마리, 제스처 포함 | ✅ | 대기·이동·오라 강화·제스처·피격·사망 |

**계산**:
- 4가지 기본형 × 각 8방향 × 6 애니메이션 상태 = **192프레임**
- 종족별 팔레트 4가지 = **192 × 4 = 768프레임**

#### 1차 전직 11종 (기본형 위에 파츠 적용)

직업별로 팔레트가 아니라 **무기·갑옷·장신구 재설계**로 구분. 기본 애니메이션은 유지.

| 전직 계열 | 비고 | 파츠 변경 내용 |
|---------|-----|--------------|
| **수호기사** | 탱 계열 | 방패 크기 증가, 갑옷 무거움 표현 |
| **광전사** | 탱 계열 | 쌍수 무기 또는 대형 한 손 무기, 분노 각인 이펙트 |
| **검사** | 딜 계열 | 얇은 날카로운 검, 신속한 자세 |
| **궁수** | 딜 계열 | 활+화살통, 이동 시 자세 변화 |
| **마법사** | 딜 계열 | 지팡이 재설계, 마력 입자 효과 추가 |
| **소환사** | 딜 계열 | 소환석/주문서, 소환수 실루엣 표시 |
| **사제** | 힐 계열 | 신성한 기구, 밝은 색상 톤 |
| **드루이드** | 힐 계열 | 자연 테마 지팡이, 식물 이펙트 |
| **음유시인** | 버퍼 계열 | 악기(현악/관악), 음파 표시 |
| **주술사** | 버퍼 계열 | 저주 토템/주술 도구, 어두운 입자 |
| **정령사** | 버퍼 계열 | 정령석/계약서, 원소 입자(화/수/풍) |

**계산**:
- 11종 전직 각각 = 기본형과 같은 8방향 × 6 상태
- 종족 팔레트 4가지 적용 = **11 × 8 × 6 × 4 = 2,112프레임**
- 총 캐릭터 스프라이트: 768 + 2,112 = **2,880프레임** (단순화 실패 시 6,000+)

#### 이동기 (직업별 형태 다름)

애니메이션 5~8프레임 각각:

| 직업군 | 이동기 형태 | 무적 표시 |
|------|----------|----------|
| 탱 | 방패 돌진 | 방패 광효과 |
| 근접 딜 | 구르기 | 주변 휘발 입자 |
| 원거리 딜 | 점멸/백스텝 | 마력 흔적 |
| 힐/버퍼 | 짧은 스텝 | 밝은 입자 |
| 소환사 | 위치 교체 | 소환수와 교환 이펙트 |

**계산**: 5가지 × 8프레임 = 40프레임 추가

#### 2차 전직 & 특수 직업

2차 전직은 1차와 **외형 강화만** 다름 (새 스프라이트 아님): 장비 업그레이드, 이펙트 강도 상승  
**특수 직업** (50층+ 드랍, 1목숨): 5~10가지 × 8방향 × 6 상태 = **240~480프레임**

**최종 캐릭터 에셋**:
- 기본 + 1차 전직: 2,880 (위)
- 2차 전직 외형 강화: 200~300 (리터칭)
- 특수 직업: 240~480 (신규)
- **총합: 3,320~3,660프레임**

### 2-3. 보스 스프라이트

**기본 설계: 개별 보스 × 8방향 고품질 애니메이션**

기획서 기준:
- **탑 5층/10층 보스**: 20개 (5·10·15·…·100층)
- **1차 페이즈 구조**: 2→3→4→5 스킬 단계 (페이즈별 신규 기믹 추가)
- **다중 등장 가능**: 같은 종류 3마리까지

#### 보스별 설계

각 보스는 **기본 + 페이즈 변화 표현**:

| 보스 티어 | 보스 수 | 기본 이미지 | 페이즈 변화 | 합계 |
|---------|--------|----------|----------|------|
| **5층 중간 레이드** | 10개 | 8방향 | 2페이즈 (색상·크기 변화) | 10 × 8 × 2 = 160 |
| **10층 대보스** | 10개 | 8방향 | 3페이즈 (격노 포함) | 10 × 8 × 3 = 240 |
| **50층+ (특수 직업)** | 10개 | 8방향 | 4페이즈 + 격노 | 10 × 8 × 4 = 320 |

애니메이션 상태 (모든 보스 공통):
- 대기 (3~5 루프 변형)
- 공격 (스킬마다 다름, 기본 2~3가지)
- 피격 (1~2프레임)
- 페이즈 진입 (각 페이즈마다 1~2프레임)

**보스 총 에셋**: 160 + 240 + 320 = **720프레임**

#### 보스 기믹 예고 표시

별도 이펙트 레이어 (기본 몬스터 레이어 위에 오버레이):
- 장판 표시 (미리 정의된 모양)
- 페이즈 진입 연출 (보스 강조 효과)
- 격노 타이머 표시

**기믹 이펙트**: 기본 이미지로 구성 (별도 스프라이트 아님)

| 이동기 | 이펙트 | 프레임 |
|------|------|------|
| 방패 돌진 | 방패 광효과 + 먼지 | 12 |

피격 이펙트:
- 일반 피격: 색상 반짝임 + 작은 튕김 (2프레임)
- 강한 피격: 방향성 넉백 + 입자 분산 (4프레임)

**피격 이펙트**: 3가지 × 6프레임 = **18프레임**

필드·던전마다 다른 분위기를 위한 배경 이펙트:

| 장소 | 이펙트 | 예시 |
|-----|------|-----|
| 평원 필드 | 먼지 입자, 풀 흔들림 | 바람 애니메이션 |

- `art/align_frames.py` — 프레임 캔버스·바닥선 정렬

**확장 계획**:

1. **캐릭터 파이프라인**:

   - 기존 4실루엣을 참조해 방향·상태만 확장

## 5. 위험 요소와 미결정 사항

### A. 코드에 영향 미치지 않는 미결정 (아트 영역)

1. **종족 실루엣 차별화 수준**
   - 현재: 팔레트 스왑 + 신체 비율 미세 조정 (제안)
   - 문제: 극한까지 단순화하면 종족 구분이 안 될 수 있음
   - 해결: 종족별 **시그니처 장식**(인간=갑옷, 엘프=갑옷 없음 + 귀, 드워프=수염, 수인=꼬리)로 보강

2. **보스 디자인 성향**
   - 기획서는 "성능 예산"만 정하고 **시각 톤(우호적·위협적·신비)은 미정**
   - 제안: 다중 등장 가능(최대 3마리)이므로 보스끼리 시각으로 구분 가능해야 함 → **계열별 색상 톤 고정** (야수=따뜻한 색, 언데드=차가운 색 등)

3. **영지 건물 규모감**
   - "아이소메트릭으로 배치할 수 있어야" → 각 건물 앰프리튜드(크기)가 얼마나 다른가?
   - 제안: **본성=가장 크고, 방어건물=가장 작음** (시각 위계 명확)

### B. 힉스필드 2D 파이프라인 한계

1. **정체성 흔들림**
   - 같은 프롬프트를 다시 넣어도 얼굴·장비·비율이 달라질 수 있다
   - 완화책: 확정 원본을 참조 이미지로 넣고, 새 디자인 생성이 아니라 상태·방향 확장으로 요청한다

2. **시트 격자 불안정**
   - 요청한 행·열과 다른 격자로 생성되거나 셀 사이 선이 남을 수 있다
   - 완화책: 분리 전 실제 픽셀 크기로 격자를 검산하고, 라벨 몽타주에서 상태 순서를 눈으로 확인한다

3. **중복 요청과 크레딧 손실**
   - 다른 세션이 같은 spec을 이미 실행했어도 로컬 폴더만 보면 다시 요청할 수 있다
   - 완화책: `ARTIFACT_INDEX.md` → 원본·Resources 검색 → `higgsfield generate list` → 실행 프로세스 순서로 확인한다

### C. 리소스 병목

1. **UI 아이콘 (스킬 55개, 장비 88개)**
   - 수작업 필수 영역이라 디자이너 1명 기준 2~3주 소요
   - 완화책: 프로토타입부터 **기본 스타일 정의** → 나머지는 템플릿 + 색상 변형

2. **영지 건물 13레벨 × 7종 = 91개**
   - 힉스필드로 각 레벨을 독립 생성하면 형태가 흔들리고 검수 비용이 큼
   - 제안: **알파 단계부터 일부만 완성** (본성·방어건물 우선), 나머지는 색상 톤 변화만 적용 (단순화)

3. **필드 타일 10티어**
   - 각 티어마다 새 색상 팔레트 = 반복 작업 → 절차형 자동화(Houdini 또는 쉐이더) 추천
   - 현재 무도구면 "기본 텍스처 5가지 + 색상 변형 10가지" 수준으로 타협

### D. 기획서에서 명시하지 않은 아트 결정사항

1. **카메라 각도**
   - ✅ **30도 쿼터뷰로 고정** — 월드 Y를 화면에서 0.5배(`sin 30°`)로 압축하고 Y 기준 깊이 정렬. 현재 `StressTest.ISO_Y=0.5` 구현과 일치
   - 캐릭터는 상반신·무기·발밑 그림자가 함께 보이게 하며, 전투와 영지에서 같은 투영 비율을 사용

2. **픽셀 해상도**
   - ✅ 기획서 §16-8 기준: **1280×720에서 캐릭터 화면상 높이 48~64px**
   - Point 필터·정수 배율을 사용하고 반픽셀 위치를 피한다. 보스는 같은 기준의 1.5~2.5배로 읽히게 한다

3. **미니맵 필요성**
   - ✅ **필드·영지·월드맵은 필수**, 고정 전투 경기장·보스전은 목표 표시로 축약
   - 미니맵용 아이콘 추가 = 30~40개

4. **캐릭터 번들링 여부**
   - 현재: "캐릭터 조합 수가 너무 많아 단순화"
   - 의문: 플레이어가 종족 변경을 원하면? (스킨처럼 구매 가능하게 할 건지?)
   - 제안: **종족 변경 불가**(기획서 명시) → 스킨은 외형(색감)만 (종족 실루엣은 유지)
