**독점 자원: 아트 원본 + Blender. 유니티는 에셋·화면 확인용으로 같이 쓴다**(오너 지시 2026-08-15)

| 만진다 | 경로·도구 |
|---|---|
| 아트 생성·정규화·대조 이미지 | `projects/ashes-to-stars/art/**` |

| **유니티 MCP** | 임포트 설정·머티리얼·에셋 배치, Play + 스크린샷으로 **자기 아트가 화면에 나오는지 확인** |

**코드가 필요하면 직접 고치지 말고 요청한다** — C#(`*.cs`)을 만져야 하는 순간이 오면
`ORDERS.md`에 **「코딩 요청」**으로 항목을 남기고(무엇이·왜 필요한지·어느 파일로 추정되는지)
개발 세션이 처리한다. 아트가 화면에 안 나오는 원인이 코드일 때가 많은데, 거기서
직접 고치기 시작하면 두 세션이 같은 파일을 만지게 된다(어제 커밋이 섞인 원인).

**배치 빌드는 개발 세션 것.** 에디터를 닫아야 하는 작업이라 겹치면 `exit 21`로 죽는다.
그래픽은 **에디터가 열린 상태에서 MCP로** 확인한다.

## 공용 규칙

1. **커밋은 자기 파일만 지정해서 add하고 곧바로 commit.** `git add -A`·`git commit -a` 금지 —
   이 저장소는 여러 세션이 master에 직접 커밋한다. 스테이징을 방치하면 남의 변경이 딸려 들어간다.
2. **유니티는 둘 다 쓰되 배치 빌드는 개발 세션만.** 에디터가 열린 상태의 MCP 조작은 둘 다
   가능하지만, 배치 빌드는 에디터를 닫아야 하므로 겹치면 `exit 21`이다. 빌드 전에는 반드시
   `ps aux | grep Unity.app/Contents/MacOS/Unity`와 `Temp/UnityLockfile`을 확인한다.
   남의 Unity를 죽이지 않는다(`-useHub`가 붙어 있으면 사람이 연 것).
3. **Blender는 그래픽 세션 것.** 개발 세션은 안 켠다.
4. 경계 판단은 **파일 확장자 하나로** 끝난다 — **`.cs`를 고쳐야 하면 개발 세션 몫**이다.
   그래픽은 그걸 「코딩 요청」으로 넘긴다. 어느 쪽인지 헷갈리면 이 규칙을 적용한다.
