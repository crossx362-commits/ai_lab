## 2. ✅ 확정된 시트 생성·분할 방식

애니메이션은 **시트 1장에 여러 프레임**을 생성하고 `split_ai_sheet.py`로 분할한 뒤 `align_frames.py`로 공통 캔버스·발밑을 정렬한다.

| 방식 | 잡몹 1종(22프레임 × 1방향) | 크레딧 |
|---|---|---|
| 프레임 단위 | 22회 호출 | **44** |
| 시트 단위 | 보통 2~4회 호출 후 분할 | 생성 결과·재시도에 따라 변동 |

시트 생성·분할은 잡몹 4종 반입으로 검증됐다. 다만 AI는 요청한 격자 수를 지키지 않을 수 있으므로 실제 행·열을 실측하고 이름 매핑을 확인해야 한다.

추가 제약: 힉스필드 출력은 마젠타 크로마키를 사용한다. `split_ai_sheet.py`로 실제 격자를 검출하고, 불일치 시 행·열을 수동 지정한다. 분할 뒤 `align_frames.py`로 22장을 같은 크기와 발높이에 맞추지 않으면 런타임 애니메이션이 떨린다.

### 실측으로 확정된 시트 생성 규칙 (2026-08-14~15)

> 예상대로 스플리터를 새로 만들었다 — `art/split_ai_sheet.py`.

| 발견 | 근거 |
|---|---|
| **AI는 요청한 격자 수를 안 지킨다** | 5×2(10셀)를 요청했더니 4×3(12셀)이 나왔다. 행·열을 미리 알아야 하는 구조면 그때마다 이름 매핑이 통째로 어긋난다 → **격자 자동 검출**이 필수다(배경이 순수 마젠타라 결정적이고 싸다) |
| **셀이 늘면 카메라 각도가 무너진다** | 6셀에서는 쿼터뷰가 유지되는데 12셀에서는 측면으로 붕괴했다. **6셀이 실용 상한**이다 |
| **각도는 숫자가 아니라 "무엇이 보이는가"로 써야 한다** | "30도 하강·45도 회전"만으로는 계속 측면이 나왔다. *"등과 어깨가 보이고 몸이 단축된다(foreshortened), 옆으로 늘어난 실루엣은 틀린 것"*으로 바꾸니 확보됐다 |
| **셀 간 크기·발 높이는 반드시 후처리로 맞춘다** | `SpriteBank`는 몹도 idle 한 장으로 배율을 정해 전 프레임에 같은 값을 쓴다 — 런타임이 편차를 흡수해주지 않는다. 공통 캔버스 + 발밑 정렬로 편차 1.54→1.08배 |
| **개수가 어긋나면 조용히 밀려 쓰지 않는다** | 이름과 그림이 한 칸씩 밀리면 걷기 프레임이 죽는 모션으로 재생되고, 화면을 봐야만 발견된다. 스플리터가 거부하고 수동 격자 지정으로 폴백한다 |

⚠️ **아직 안 풀린 것**: 6셀로 각도를 확보하면 이번엔 **포즈 차이가 약해진다**(idle과 walk가 거의 같은 그림). 자세를 극단적으로 서술하는 쪽으로 다음 라운드에서 다룬다.

### ⚠️ 앵커와 팔레트 스왑의 충돌 — P0에서 반드시 확인할 것

문서 §5는 잡몹 프롬프트에 `neutral gray-white base color for palette swapping`을 **가장 중요한 구절**로 지정했다. 계열 5색을 색조 셰이더로 입히려면 원본이 무채색이어야 하기 때문이다.

그런데 **우리 앵커는 채도가 높다**(탱=청/금, 딜=흑/자주). 앵커가 화풍과 함께 *색까지* 전이시키면 무채색 요구가 깨지고 **계열 구분 전체가 무너진다.**

→ P0에서 "앵커를 물린 채로 무채색이 나오는가"를 별도로 확인한다. 안 되면 **잡몹 전용 무채색 앵커**를 따로 만든다(기존 몹 스프라이트를 회색조 변환해 사용).

### ✅ C1. 방향 — **(A) 1방향 + 좌우 반전으로 확정** (오너 결정 2026-08-14)

> 📌 **초판 정정**: 초판은 "flipX를 런타임에 아무도 안 건드린다"고 적었으나 **틀렸다.**

- **(A) 방향을 포기한다** — 1방향만 뽑고 이동 방향은 `flipX`로 좌우만. 물량이 **1/3**로 준다(잡몹 178→60, 보스 552→184). 뱀서라이크는 화면에 수백 체가 나와 개별 방향이 잘 안 보인다는 §0-A의 논리를 한 단계 더 밀면 여기까지 온다
- **(B) 방향을 지원한다** — 파일명에 방향 자리를 넣고(`<유닛>_<상태>_<방향>_<번호>`), `SpriteBank`에 방향 인자를 추가하고, 렌더러가 이동 벡터로 방향을 고르게 한다. **코드 작업이 선행**돼야 한다

⚠️ **어느 쪽이든 리소스를 뽑기 전에 정해야 한다.** 나중에 뒤집으면 3배를 버리거나 3배를 다시 뽑는다.

### 🔴 C2. 아틀라스가 이미 58% 찼다 — W4 물량이 그대로 들어가면 조용히 뭉개진다

`SpriteBank`는 전부를 **4096² 런타임 아틀라스 한 장**에 넣는다(배칭이 W1 성능의 전제). 코드 주석이 이미 경고한다: *"아틀라스가 넘치면 PackTextures가 **조용히 축소**해 스프라이트가 뭉개진다."*

실측(2026-08-14):

| 구간 | 장수 | 면적 |
|---|---|---|
| 직업 4종 (tank·dps·healer·buffer) | 52 | 6.45 Mpx |
| mob01 | 22 | 0.50 Mpx |
| 루트 플레이스홀더 | 8 | 2.23 Mpx |
| ranged (미사용) | 5 | 0.62 Mpx |
| **합계 / 4096²=16.78Mpx** | **87** | **9.77 Mpx (58%)** |

**캐릭터 평균 크기(124k px) 기준 약 56장밖에 안 남는다.** W4 계획은 잡몹 132장 + 보스 138장이다 — 그대로는 못 들어간다.

> ✅ **조치 완료 (2026-08-14)**: `SpriteBank.Load()`가 담기 **전에** 면적을 재서 70% 경고 / 85% 에러를 낸다.
> 근본 문제는 용량이 아니라 **실패가 조용하다는 것**이었다 — 넘쳐도 예외가 없고 화면도 그럴듯해서 도트가 뭉개진 채 몇 주를 갈 수 있다. 소리를 지르게 만드는 것이 수리다.
>
> **생성 규칙**: 새로 뽑는 아트는 **높이 128px로 저장한다**(`aigen.py --height 128`). 화면상 캐릭터는 2유닛 ≈ 108px이라 128px면 충분하고, 오너 아트의 416×297은 3.2배 낭비다. (A) 확정으로 W4는 110장이라 당장은 69%로 들어가지만, 전체 예산 400장을 416px로 넣으면 3배 초과한다.

→ **해결: 아틀라스 입력을 128px로 정규화한다.** 문서 §2가 이미 "런타임 스프라이트 128px"로 정해둔 규격인데 **현재 오너 아트는 416×297 원본 그대로 들어가 있다**(3.2배 낭비). `SpriteBank`는 PPU를 내용 높이로 역산하므로 128px 입력이어도 화면 크기는 그대로다. 정규화하면 캐릭터 구간이 6.45→0.63Mpx로 줄어 **여유가 10배**가 된다.
- 화면상 캐릭터는 2유닛 ≈ 108px로 보인다 → 128px 원본이면 충분하고 416px는 낭비다
- 루트 플레이스홀더 8장(2.23Mpx)과 미사용 `ranged/` 5장(0.62Mpx)은 교체·정리하면 추가로 비워진다

### 🔴 C3. 스타일 앵커의 채도가 계열 색조를 죽인다

계열 5종 구분은 `ProjectSetup.cs:343`의 `sr.color = m.색조` **한 줄**에 달려 있다. 이것은 **곱셈 틴트**라 원본이 무채색일 때만 5색이 서로 구분된다 — 프롬프트 문서 §5가 `neutral gray-white base color for palette swapping`을 "이 4줄에서 가장 중요한 구절"이라고 못 박은 이유다.

그런데 **우리 앵커는 채도가 높다**(탱=청/금, 딜=흑/자주). 앵커가 화풍과 함께 색까지 전이시키면 계열 구분 전체가 무너진다.

> ✅ **조치 완료 (2026-08-14)**: `art/anchor_mobs_gray.png` 생성 — 오너 `mob01` 아트 6포즈(idle·walk·attack·death)를 회색조 변환하고 밝기를 1.15배+18 올렸다. **어두우면 어떤 색을 곱해도 검다**는 곱셈 틴트의 성질 때문에 팔레트 스왑 여지를 남겨야 한다.
> 포즈를 6개 넣은 것은 화풍뿐 아니라 **동작 범위**까지 참조시키기 위해서다.
>
> ⚠️ P0에서 "앵커를 물린 채 정말 무채색이 나오는가"를 반드시 확인한다 — 앵커가 회색이어도 프롬프트의 계열 서술(`matted fur`·`brass gears`)이 색을 되살릴 수 있다.

→ **잡몹·보스 전용 무채색 앵커를 따로 만든다.** 기존 몹 아트를 회색조 변환해 앵커로 쓰고, P0에서 "앵커를 물린 채 무채색이 나오는가"를 반드시 확인한다.

### 🟠 C4. 프레임 규격이 문서와 코드에서 어긋나 있다

|---|---|---|

| 잡몹 | `MOB_FRAMES` **22 고정** (idle4·walk6·atk4·hurt4·death4) | idle2·walk2·attack2·hurt1·death3 = **11** |

> ✅ **결정 (2026-08-14): 코드(22프레임)에 맞춘다 — 프롬프트 문서 v0.2에 반영 완료.**

### 🟠 C5. 몹의 추가 상태를 재생할 슬롯이 없다

→ 돌진 예고 0.8초를 뽑아도 **재생할 방법이 없다.** `Motion` enum과 `MobAnim`을 먼저 확장해야 한다.
