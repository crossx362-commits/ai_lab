# 자율 개발 루프 지시서

이 세션은 이전 대화를 이어받지 않는 완전히 새 세션이다. 기억은 파일과 Git 기록만 사용한다.

### ① 합격 기준

- 자동검사와 실제 게임 실행을 모두 확인하고, 다른 사람이 봐도 경쟁력이 있는 완성도인지 판단한다.
- 치명 결함은 0개, 적용 가능한 항목은 각각 4/5 이상, 종합 85/100 이상일 때만 합격이다.
- 기능·조작성·가독성·연출·성능·회귀를 실제 증거로 확인한다. 보지 않은 화면을 봤다고 쓰지 않는다.

### ② 먼저 읽을 문서

1. `DIRECTIVES.md`, `AGENTS.md`, 작업 경로에서 가장 가까운 `CLAUDE.md`를 읽고 안전 규칙을 지킨다.
2. `docs/feedback/INBOX.md`를 가장 먼저 처리한다.
3. `docs/STATUS.md`에서 완료된 작업과 다음 일을 확인하고, Git 브랜치·커밋도 살펴 다른 AI 작업을 중복하지 않는다.
4. `GAME_WORKLOG.md`나 `ORDERS.md`가 있으면 읽고, 마지막으로 `docs/DESIGN.md`와 대상 기능 문서를 확인한다.

### ③ 규칙과 근거

- 배정된 한 작업과 `write_paths`만 수정한다. 다른 worker의 경로, master, `autonomous/integration`, 다른 worktree는 건드리지 않는다.
- worker와 reviewer는 서로 다른 제공자여야 하며 자기 작업을 스스로 최종 승인하지 않는다.
- 그림은 Higgsfield 또는 Grok Imagine만 사용한다. 둘 다 쓸 수 없으면 약한 대체물을 만들지 말고 보류 사유를 남긴다.
- 게임은 상시 폴리싱하되 기존 완성 자산을 먼저 재사용하고 중복 리소스 재생성 금지를 지킨다. 기본 5직업·몹 개선은 허용하며, 할로우 나이트 화풍 강제는 취소됐다. 영지 화면·EstateYard도 실제 게임 흐름과 함께 확인한다.
- 스프라이트는 프레임 간격, 셀 크기, 중심축, 잘림·여백·알파, 실제 게임 크기와 애니메이션 흔들림을 확인한다.
- Ollama는 중복 문장 제거·형식 변환 같은 비판단 작업에만 쓸 수 있다. 게임 코드·설계·밸런스·QA·시각 판정·리뷰에는 쓰지 않는다.
- resume/continue로 이전 대화를 잇지 않는다. 범위를 넓혀야 하면 새 작업으로 남긴다.

### ④ 한 바퀴 도는 순서

읽기 → 한 작업 구현 → 자동검사 → 화면 보기 전에 정확한 파일만 커밋 → 실제 실행·육안 확인 → 문제가 있으면 다시 검사·새 커밋 → 다른 제공자의 독립 검토 → coordinator가 통합·STATUS 갱신.

병렬 작업은 write path가 겹치지 않을 때만 각각의 격리 worktree에서 수행한다. 완료 순서가 아니라 작업 ID 순서로 검토·통합한다.

### ⑤ 커밋 순서 규칙

- 검사를 통과하면 화면을 보기 전에 먼저 커밋한다. 화면 확인 후 수정했으면 검사하고 새 커밋을 남긴다.
- 한 바퀴는 도중에 멈출 수 있다. 멈춘 자리에 커밋이 없으면 그 작업은 보존되지 않는다.
- `git add -A`나 `git commit -a`를 쓰지 말고 고친 파일만 명시해 한 호흡으로 stage·commit한다.
- STATUS는 worker가 직접 고치지 않는다. 독립 검토를 통과한 정확한 커밋만 coordinator가 `autonomous/integration`에 합치고 인수인계를 기록한다.
