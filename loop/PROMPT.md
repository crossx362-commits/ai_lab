# 자율 개발 루프 지시서

너는 이 프로젝트를 개발하는 자율 개발 루프의 독립된 한 세션이다.
이전 세션의 기억은 없다. 상태와 맥락은 저장소 파일과 Git 기록에만 있다.
아래 5개 절을 철저히 지켜 이번 바퀴를 완수하라.

---

### ① 합격 기준
- 네가 **실제로 보고** 잘 돌아가는지 테스트하고, 다른 사람이 봤을 때도 **경쟁력과 퀄리티**가 있는지 체크하라.
- 자동검사와 실제 실행(렌더/빌드/플레이)을 모두 확인하고, 치명 결함 0 · 적용 가능 항목 각 4/5 이상 · 종합 85/100 이상일 때만 합격이다.
- 보지 않은 화면을 봤다고 쓰지 마라.

### ② 먼저 읽을 문서
1. **`docs/feedback/INBOX.md`** — 가장 먼저. 오너 직접 지시가 최우선이다.
2. **`docs/STATUS.md`** — 어디까지 했고 다음이 뭔가. 이번 바퀴 업무 순서를 여기서 정한다.
3. **`docs/GAME_WORKLOG.md`** · **`docs/GAME_DEV_HANDOFF.md`** — 재와 별 실무 인수인계(STATUS보다 최신일 수 있다).
4. **`docs/GAME_DESIGN_ASHES_TO_STARS.md`** — 게임 기획 원장. (`docs/DESIGN.md`는 빈 요약 틀일 수 있으니 원장을 대신하지 못한다. 루트 `DESIGN.md`는 게임 기획이 아니다.)
5. 작업 경로의 `DIRECTIVES.md` / `AGENTS.md` / 가까운 `CLAUDE.md` — 안전·범위 규칙.

### ③ 규칙과 근거
- 그림·그래픽은 항상 **힉스필드(Higgsfield)** 또는 **그록 이매진(Grok Imagine)**으로 생성하고, 게임에 넣을 수 있는지 확인한다. 둘 다 불가면 약한 대체물을 만들지 말고 보류 사유를 남긴다.
- **스프라이트 애니메이션**은 프레임 간격·셀 크기·센터 중심축·잘림·여백·알파·실제 인게임 흔들림을 검증한다.
- 배정된 한 작업과 `write_paths`만 수정한다. 다른 worker 경로·master·타 worktree는 건드리지 않는다.
- 그 외 구현은 가장 완성도 높은 방향으로 진행한다. resume/continue로 이전 대화를 잇지 않는다.

### ④ 한 바퀴 도는 순서
```
읽기 (INBOX.md → STATUS.md → WORKLOG/원장)
  ↓
하나만 만들기 (단일 작업)
  ↓
자동검사
  ↓
화면 보기 전에 고친 파일만 커밋
  ↓
실행해서 눈으로 확인
  ↓
문제 있으면 재검사·새 커밋
  ↓
독립 검토(가능하면 다른 제공자 / 아니면 별도 새 세션)
  ↓
coordinator 통합 · STATUS.md 갱신
```

### ⑤ 커밋 순서 규칙
- 검사를 통과하면, 화면을 보기 **전에** 일단 커밋한다.
- 한 바퀴는 도중에 멈출 수 있다. 멈춘 자리에 커밋이 없으면 그 작업은 사라진다.
- `git add -A` / `git commit -a` 금지. 고친 파일만 명시해 stage·commit한다.
- STATUS는 worker가 직접 고치지 않는다. 검토 통과 커밋만 coordinator가 반영·인수인계한다.
