# 기획서 대비 구멍 표 (2026-09-06)

판정 기준은 **「플레이어가 화면에서 도달할 수 있는가」**다. 코드가 있어도 화면에 없으면 ②다.
표만 낸다 — 고치지 않았다. 우선순위는 검수가 정한다.

- ① 구현 — 플레이 화면에서 쓸 수 있고 결과가 보인다
- ② 일부 — 서버·데이터에는 있으나 화면이 없거나, 규모/형태가 기획서에 못 미친다
- ③ 없음 — 코드에도 없다

기계적으로 확인한 것: 서버 공개 행동 API(`Try*`/`Gm*`) 87개 중 **클라이언트에서 호출하지 않는 것은
`TryEnemyStrike` 하나**(몹 AI 전용)다. 즉 「서버에만 있고 UI가 없다」류의 구멍은 아래 표의 ②로 좁혀진다.

## 눈에 띄는 구멍 요약(고치지 않음)

1. **소리·VFX가 0이다** — 폴더가 비어 있다. 전투·제작·UI 전부 무음이고 마법이 숫자로만 발생한다.
2. **영구 저장이 JSON 파일이다** — 기획서의 PostgreSQL·테이블·트랜잭션이 없다. 외부 접속·전용 서버 검증도 없다.
3. **서버에만 있고 화면에 없는 값 2개** — 도구 사용 횟수(`ToolUses`), 동료 슬롯(`CountFollowers`).
4. **UI가 IMGUI 기본 버튼이다** — Paperdoll·드래그앤드롭·대상 지정 커서·우클릭 메뉴가 없다.
5. **관심 영역·LOD·부하 테스트가 없다** — 성능 항목은 통째로 미착수.
6. **몬스터 14종/20종, 방어구 세트가 얇다** — 콘텐츠 상한에 못 미치는 두 곳.
7. **수리가 「다시 제작」에 얹혀 있다** — 대장간에 수리 행동이 따로 없다.
8. (곁가지·**정정**) 앞선 판에서 나는 `AssertStrengthRequirement`가 「이름과 달리 랜드마크만 검사한다」고
   적었다. **틀렸다** — 앞 20줄만 읽고 단정했다. 그 게이트는 요구 STR을 실제로 검증한다(철검 strReq=25,
   저 STR 장착 거부·고 STR 장착 성공을 `EquipResolve`와 `TryEquip` 양쪽에서, 실패 사유 `str_req`까지).
   진짜 문제는 다른 것이었고 고쳤다: **마을 랜드마크 전제가 게이트 25곳에 복붙**돼 있어 「봉합 주문」
   게이트가 마을 장식을 검사하고 있었다 → 공용 `AssertVillageIntact()`로 뽑았다.
