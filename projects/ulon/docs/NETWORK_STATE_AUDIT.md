> **읽는 사람에게 먼저**: 지금의 울온은 **온라인이 되는 게임이 아니다.**
> 두 클라이언트가 붙어서 서로를 보고 움직이지만, **각자 다른 세계를 시뮬레이션하고

## 3. 뿌리는 SyncVar 누락보다 한 겹 더 깊다

1. **클라가 자기 시뮬레이션을 따로 돌린다.** `Server/OfflineWorld.cs:232 Update()`에
   네트워크 가드가 없다 — 시체·독·시전·펫·경비·`RecalcFromStr`가 클라에서도 매 프레임 tick한다.
   마나가 두 클라에서 다른 값인 것이 그 증거다. **못 받아서 0인 게 아니라 혼자 만들어 낸다.**
2. **클라의 캐릭터는 영영 로드되지 않는다.** `CharacterBinder.Apply`는
   `Client/NetAvatar.cs:53`, 즉 `[ServerRpc] RpcBind` 안에 있다 — 서버에서만 돈다.
   클라 화면의 「나」는 **빈 프리팹**이다.

→ 그래서 **SyncVar만 붙여도 안 고쳐진다.** 클라 시뮬레이션이 매 프레임 덮어쓴다.

## 4. 기획서와 어긋나는 지점 (사실 고정)

| 기획서 | 문장 | 지금 코드 |
|---|---|---|
| §14 위험 대응(`GAME_DESIGN.md:417`) | 서버 치트 — 골드/스킬/아이템 조작 → **「서버 권한형, 거래/제작 로그」** | 골드·스킬이 클라 자체값이라 **서버 권한형이 성립하지 않는다** |
| §NPC·성장(`GAME_DESIGN.md:662`) | **「Skill Gain은 서버가 판정」** | 검술 하나만 서버 판정이 화면에 도달, 나머지 28개는 클라가 혼자 올린다 |
| §13.1 MVP 완료 정의 | 2명 접속 → 사냥 → 스킬 성장 → 아이템 → 거래 → 은행까지 한 사이클 | 사냥·성장·아이템·은행의 **화면 값이 클라 자체값**이라 이 사이클은 아직 「보이는 것」일 뿐이다 |

**결론: 지금 상태로는 치트 방지가 원리적으로 성립하지 않는다.**

## 5. 다음 사람이 하지 말아야 할 것

- **SyncVar를 값마다 하나씩 붙이지 마라.** 절반만 서버 권위인 상태는 지금보다 나쁘다 —
  어느 값이 진짜인지 아무도 모르게 된다(검수 판정 2026-09-08).
- 갈림길은 두 개이고 **함께** 정해야 한다:
  ① 값마다 SyncVar인가, **「내 상태」를 한 RPC로 미는가**(파티·길드가 이미 쓰는 형태, 축이 30개 넘는다).
  ② **클라의 `OfflineWorld` 시뮬레이션을 끄는가**. ②를 안 하면 ①만으로는 안 고쳐진다.
- 오너 판정 전까지 **네트코드 수정 금지**.
