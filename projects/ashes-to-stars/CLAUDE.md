# 재와 별 — 개발 관리 (항상 참고)

> 이 파일은 `projects/ashes-to-stars/` 아래에서 작업하는 모든 세션에 자동으로 로드된다.
> **오늘 세션이 어디서 왔든 이 문서부터 읽는다.** 다른 문서와 충돌하면 §0 권위 순서를 따른다.

## 0. 권위 순서 (충돌 시 위가 이긴다)

1. **오너의 직접 지시** (이 대화)
2. `docs/GAME_DESIGN_ASHES_TO_STARS.md` — ✅=확정 · 💡=제안 · ⚠️=주의 · 📌=폐기
3. `docs/GAME_SPEC_*.md` (각 문서 머리말이 상위 문서를 명시)
4. `docs/GAME_ART_RESOURCES.md` §0-B — 아트 물량의 최종 권위
5. 이 문서, `docs/GAME_SESSION_BOUNDARY.md`
6. 코드 — **문서와 다르면 문서가 맞다고 가정하지 말고, 왜 다른지 먼저 확인**

## 1. 지금 뭘 해야 하나 → `output/qa/ashes-to-stars/ORDERS.md`

기획서 기반 자동 회의(`game_council.py`, 09:00·21:00)가 낸 작업지시서. **위에서부터 순서대로.**
각 항목에 통과 기준·네거티브 컨트롤이 있다 — 코드를 넣은 것과 끝난 것은 다르다.

## 2. 세션 경계 → `docs/GAME_SESSION_BOUNDARY.md`

주제가 아니라 **자원**으로 가른다. 판단 기준은 확장자 하나: **`.cs`면 개발 세션, 그 외는
그래픽 세션이 직접**(그래픽도 Unity MCP·Blender를 쓴다 — 배치 빌드만 개발 세션 전용).
애매하면 그 문서를 펼쳐서 표로 확인한다.

**커밋은 자기 파일만 지정해서 add하고 곧바로 commit.** `git add -A`/`git commit -a` 금지 —
여러 세션이 master에 동시에 직접 커밋한다. 스테이징을 방치하면 남의 변경이 딸려 들어간다.

## 3. 유니티는 둘 다 쓴다 — 락은 사본으로 푼다

`unity/` 원본과 `unity_meas/` 사본이 있다(`sync_meas.sh`로 동기화). 에디터가 원본을 잡은
채로 사본에 배치를 걸 수 있다(실측 확인, `538701c8`). **배치 빌드 전에 반드시 확인**:
```
ps aux | grep "Unity.app/Contents/MacOS/Unity" | grep -v VBCSCompiler
ls unity/Temp/UnityLockfile
```
비어 있으면 원본에 진입, 아니면 `unity_meas/`를 쓰거나 기다린다. 남의 Unity를 죽이지 않는다
(`-useHub`가 붙어 있으면 오너가 직접 연 것).

## 4. 자동진행 — Stop 훅

`autopilot_stop_hook.py`가 지시서(ORDERS.md)가 남아 있으면 세션이 멈추지 않게 되돌려보낸다.
- 옵트인 대상만 걸린다(`.claude/autopilot_sessions.txt`) — **런타임 session_id**로 등록해야
  한다. `list_sessions`가 주는 `local_xxxx`(앱 id)와는 다른 값이니 착각하지 말 것.
- 자기 몫을 다 끝냈으면 `mkdir -p output/qa/ashes-to-stars/autopilot_done && touch .../$CLAUDE_SESSION_ID`.
  **`ORDERS.md`에 `# 완료`를 적는 방식은 폐기했다** — 그 파일은 공유 자원이라 한 세션의
  완료 선언이 다른 세션까지 풀어버렸다(실측 사고, `e6ac9b72`).
- 같은 지시서로 20턴 상한. 새 지시서가 오면 카운터 자동 초기화.

## 5. 아트를 만들었으면 반드시 반입까지

`Resources.Load`는 문자열로 찾는다. **이름이 같아도 내용이 낡으면 조용히 낡은 채로 남는다**
— 파일 목록만 봐서는 안 보인다(실측 사고: `Resources/props` 32장이 전부 어제 버전인데
아무도 16시간 몰랐다). 생성할 때마다:

```bash
python3 projects/ai-team/skills/마루_게임개발/tools/game_asset_names.py
```
누락·낡음·잡동사니·meta 불일치를 코드 기준으로 판정한다(문서 기준 아님 — 코드가 실제로
찾는 이름을 소스에서 뽑아 대조한다). **생성 사이클(QC 훅 옆)에 물려서 만들 때마다 돌게 할 것.**

반입 후: `read_console`로 `[FieldDecor] 프랍 누락`류 경고 0건 확인 → Play + 스크린샷으로
**실제로 달라 보이는지** 육안 확인. png 수 = png.meta 수 대조.

## 6. 감시 체계

| 무엇을 | 어디서 | 못 하는 것 |
|---|---|---|
| 세션 정체·생성물 표류·측정 공회전 | 예원 (`game_session_watch.py`, 10분, launchd 상주) | **유휴 세션을 깨우지 못한다** — 경보만 |
| 자동진행 | Stop 훅 (§4) | 세션이 훅 발동 전 상태면 무력 |
| 다음 작업 판정 | `game_council.py` (하루 2회) | — |
| 역할별 상시 점검 | `game_agents.py` (읽기 전용 6인) | **빌드·플레이 검증 없음** — 유니티 락과 안 다투게 의도적으로 뺐다 |

세션이 멈춰 있으면 **창을 한 번 열어야 재개된다.** 크로스 세션 메시지·Stop 훅·예원 경보
전부 "돌고 있는 세션"을 전제로 하고, 멈춘 세션을 프로그램적으로 깨울 수단은 없다.

## 7. 이 프로젝트에서 반복해서 겪은 함정

전체 목록은 `docs/GAME_DEV_HANDOFF.md` §5. 그중 세션 관리에서 새로 나온 것:

- **커밋 오염** — 두 세션이 같은 파일(C#)을 만지면 한쪽 커밋이 다른 쪽의 미커밋 변경을
  쓸어담는다. §2의 확장자 경계로 막는다.
- **표류하는 생성물** — "만들었다"와 "게임에 들어갔다"는 다르다. §5의 검사기로 막는다.
- **공유 파일에 개별 신호** — 완료·상태를 여러 세션이 쓰는 파일에 적으면 한쪽 신호가
  다른 쪽에 새어나간다. 세션별 파일(`autopilot_done/<id>`)로 분리한다.
- **측정 배속** — 시뮬레이션이 `Time.deltaTime` 실시간 누산이면 게임 내 시간만큼 실제로
  걸린다. `dt`가 고정 스텝이면 프레임당 스텝 상한을 풀어도 결정론은 안 깨진다(단 배속
  전/후를 같은 시드로 돌려 CSV가 완전히 일치하는지 반드시 확인).
- **회의가 미병합 브랜치를 못 봄** — `git status`는 워크트리 밖 변경을 안 보여준다.
  이미 있는 걸 "새로 구현하라"고 지시할 수 있다 — 병합 전 `git branch`·`git worktree list`
  확인.
