## 6-A. 2026-08-15에 드러난 것 — 전부 「로그는 정상인데 화면은 아니다」 계열

- **`PackTextures`는 정규화 UV를 돌려주고 `Sprite.Create`는 픽셀 Rect를 받는다.** 그걸 그대로
  넘겨서 **프랍이 도입 이래 한 번도 안 그려지고 있었다.** 그런데 로그는 `프랍 90개 배치`로
  멀쩡했다. **화면이 비었는데 수치가 정상이면 이 계열부터 의심하라.**
- **보스 패배 콜백이 결과 화면만 열고 목숨 경계를 안 부르면 V4가 통째로 거짓이다.** `OnPartyWiped`(힐체크 실패)는 예전에 요약만 쓰고 `RegisterDeath`를 안 불렀다. 전멸·힐체크 실패는 같은 `GameFlow.ApplyPveDefeat`를 타야 한다 — 출전 슬롯만, 로스터 전원 아님.
- **`prop_scale.json`(프랍 목표 크기표)이 만들어진 채 읽는 코드가 0곳이었다.** PPU 32 고정이라
  128px 원본이 전부 4유닛 = 캐릭터의 2배였다. 이 저장소의 미구현은 거의 항상 이 모양이다 —
  정의는 있고 부르는 곳이 없다(`CombatStyleDef`·보스 기믹·`RaceDef`가 전부 그랬다).
  **✅ 확정 기능이 화면에 없으면 `grep -rn`으로 소비처 개수부터 세라.**
- **`Assets/_Game/Art`에 스프라이트를 두지 마라.** `Resources.Load`가 못 읽어 화면엔
  플레이스홀더만 나온다(2026-08-13). 런타임 아트는 `Assets/Resources/`만. 빈 함정 폴더는
  2026-08-16에 삭제했고 `game_asset_names.py`가 재발을 막는다.
- **`Resources`에 코드가 안 읽는 그림을 두지 마라.** 검사기는 누락만 보다가 미사용 FX·아틀라스를
  놓쳤다(2026-08-16). `game_asset_names.unused_resource_problems()`가 소비 목록과 대조한다.
- **임시 대체물이 본물을 가리면 결함이 결함으로 안 보인다.** 스킬 이펙트 로딩이 상시 실패했는데
  (`Resources.Load<Sprite>`인데 png가 Texture2D로 임포트된다) 절차 생성 흰 원 폴백이 대신
  떠서, 몇 달 동안 "이펙트는 나온다"로 보였다. 폴백을 넣을 땐 **폴백이 떴다는 사실 자체가
  눈에 띄게** 하라.
- **상한을 훑기 루프의 조건에 걸지 마라.** `for (...; placed < CAP; ...)`은 상한에 닿는 순간
  훑기를 멈춰서 **결과가 맵 한쪽에만 몰린다.** 후보를 다 모은 뒤 균일하게 솎아낼 것.
- **개수를 손으로 적은 상수는 양방향으로 틀린다.** `ScatterCount`가 그랬다 — 작으면 새 프랍이
  조용히 안 나오고, 크면 집이 들판에 흩뿌려진다. **목록에서 직접 세게 하면 그 부류가 사라진다.**
- **바닥에 큰 원을 그리지 마라.** 그게 무엇이든(범위 표시든 고리길이든) 화면에서는 스킬
  범위 표시로 읽힌다. 오너가 네 번 지적했고 매번 다른 것이었다.
- **초승달(`fx_slash`)도 바닥에 깔면 금색 고리다**(2026-08-18). 돌진 예고는 먼지뿐. 고리·원환·초승달은 예고가 아니다.
- **스프라이트 적용 = 화면에서 흰 사각형이 없다.** 바둑판·흰 종이 잔재를 안 재고 "붙였다"고 하면 캐릭터가 흰 카드가 된다. `leftover_white_pct`로 재고, 가면(뼈색)은 통째로 지우지 마라.

`loop/loop.sh`가 도는 동안 오너와의 대화 세션도 같은 저장소를 고친다. 2026-08-15에 실제로
나무 반입을 양쪽이 동시에 해서 `prop_scale.json`과 프랍 목록에 같은 항목이 **두 벌** 들어갔고,
정리하는 쪽 쓰기가 다른 쪽 편집을 덮었다. 그 결과 자연물 13종인데 산포 상한이 14가 되어
집이 들판에 흩뿌려질 뻔했다.
- 큰 파일을 고치기 전에 `git log --oneline -12`와 `git status`로 상대가 뭘 잡고 있는지 본다
- 파일 전체를 읽어 문자열 치환으로 되쓰는 방식(python read→replace→write)은 **그 사이의
  남의 편집을 통째로 날린다.** 공유 파일에는 Edit 도구처럼 좁은 범위 치환을 쓸 것
- **공유 파일(`W3Party.cs` 등)을 만질 땐 `touch loop/HOLD`**. 루프가 이터레이션 경계에서
  기다렸다가 파일을 지우면 **스스로 재개**한다(STOP과 다르다 — STOP은 사람이 다시 켜야 하는
  종료다). 30분 방치되면 루프가 알아서 푼다(`LOOP_HOLD_MAX`).
  ```bash
  touch loop/HOLD && <작업> && git add <파일> && git commit && rm loop/HOLD
  ```
- **작업 직후 즉시 커밋한다.** 미커밋 변경을 공유 파일에 남겨두면 루프가 그 파일을 커밋할 때
  통째로 쓸려간다 — 2026-08-15에 실제로 났다(스킬 연출 변경이 보스 소환 커밋에 섞였다).

검사기를 돌려라** — 그게 커밋 누락을 잡는 유일한 자동 장치다.

## 정기 잡 — crontab은 비었다 (2026-08-15)

**launchd(`com.ailab.*`)가 유일한 정기 잡 관리자다.** crontab은 비워 뒀다.

이유: 크론에 남아 있던 10줄이 **전부 삭제된 에이전트**의 것이었고, 그중 9줄은
스크립트 파일 자체가 없어 매일 조용히 실패하고 있었다(루나·아린·가희·현빈·티모 +

## 7. 이 프로젝트에서 반복해서 겪은 함정

전체 목록은 `docs/GAME_DEV_HANDOFF.md` §5. 그중 세션 관리에서 새로 나온 것:

- **프로토 %가 80에서 안 오르면 사람 관문 대기가 아니라 집계 버그다**(2026-08-16).
  10세션 삭제가 있는데 V4b를 0으로 고정하면 4/5=80%가 영구가 된다.
  실측은 `v4_gate_pct`로 올리고, 사람 70% 통과 또는 오너 「넘김」만 100이다.
  넘김을 테스터 통과로 쓰지 마라. 「80% 유지」는 수리가 아니다.

- **커밋 오염** — 두 세션이 같은 파일(C#)을 만지면 한쪽 커밋이 다른 쪽의 미커밋 변경을
  쓸어담는다. §2의 확장자 경계로 막는다.
- **표류하는 생성물** — "만들었다"와 "게임에 들어갔다"는 다르다. §5의 검사기로 막는다.
- **공유 파일에 개별 신호** — 완료·상태를 여러 세션이 쓰는 파일에 적으면 한쪽 신호가
  다른 쪽에 새어나간다. 세션별 파일(`autopilot_done/<id>`)로 분리한다.
- **측정 배속** — 시뮬레이션이 `Time.deltaTime` 실시간 누산이면 게임 내 시간만큼 실제로
  걸린다. `dt`가 고정 스텝이면 프레임당 스텝 상한을 풀어도 결정론은 안 깨진다(단 배속
  전/후를 같은 시드로 돌려 CSV가 완전히 일치하는지 반드시 확인).
- **회의가 미병합 브랜치를 못 봄** — `git status`는 워크트리 밖 변경을 안 보여준다.
  이미 있는 걸 "새로 구현하라"고 지시할 수 있다 — 병합 전 `git branch`·`git worktree list`
  확인.
