# AutoDev v2 핵심 지침

이 문서는 재와별 AutoDev v2의 **상시 규칙**이다. 매 작업에서 이것만 기본 지침으로 사용한다. 과거 회의록·장문 운영문서·사고이력은 자동으로 읽지 않는다.

## 목표
- AI 사용량이 아니라 **실제로 플레이 가능한 기능 완성**을 최우선으로 한다.
- 플레이 루프: 영지(성장·전직·합성) → 출전 편성 → 필드/던전/보스 전투 → 보상 → 영지.
- AI는 판단과 코드 작성에만 쓴다. 검색·Git 상태·로그 필터·컴파일·테스트는 로컬 프로그램이 처리한다.
- `docs/STATUS.md`와 `loop/` 보드는 AutoDev v2의 작업 큐가 아니다. 아트/ox-alpha/폴리싱 다음 줄을 작업으로 만들지 않는다.

## 역할
- Director: 큐가 비었을 때만 Grok 1회로 다음 4~6개 작업을 만든다. 코드 수정 금지.
- Task Queue: 선행조건과 우선순위로 다음 작업을 로컬에서 선택한다. AI 호출 금지.
- Worker: Grok이 현재 작업 하나만 구현한다.
- Verifier: 로컬 컴파일/테스트/빌드 결과로 완료를 판정한다.
- Fallback: Grok이 같은 문제를 해결하지 못했을 때만 Codex 1회. Claude는 사용하지 않는다.

## 컨텍스트 제한
- 프로젝트 전체를 모델에 넘기지 않는다.
- 관련 파일 후보는 기본 최대 5개.
- 전체 Unity 로그 대신 오류 주변만 전달한다.
- 이전 대화 세션을 이어붙이지 않는다. 작업마다 새 세션.
- 진행상태는 대화가 아니라 `state.json`에 저장한다.
- `GAME_WORKLOG.md`, `ORDERS.md`, 회의록, 역할별 감사 리포트를 작업마다 갱신하지 않는다.

## 작업 단위
좋은 작업은 한 세션에서 구현하고 검증 가능한 플레이 결과다.
예: 승리 후 보상 지급, 장비 착용 후 능력치 반영, 적 스폰부터 사망까지 정상 동작.

피할 것:
- 상태문서 갱신만 하는 작업
- 관련 없는 리팩터링
- 전체 아트 통일
- 이미 동작하는 주변 코드 개선
- 다음 작업까지 한 Worker가 임의로 확장

## 완료 규칙
- AI의 '완료했습니다'는 완료 판정이 아니다.
- 검증기가 PASS해야 완료다. 로컬 검증은 마루 스킬(`game_compile_check.py`) + 필요 시 Unity Acceptance다.
- 오너 Unity가 열려 있으면 구현은 진행할 수 있지만 완료 판정은 보류한다(`implement_while_unity_locked`).
- 완료 조건을 만족하면 더 개선하지 말고 즉시 종료한다.
- 같은 검증 실패가 반복되거나 작업트리 변화가 없으면 루프를 중단한다.
- 해결 불가 시 BLOCKED로 기록하고 다음 모델/사람에게 원인만 전달한다.

## 안전
- 기존 미커밋 변경을 되돌리지 않는다.
- `git push`, force-push, 배포, 외부 게시, 결제는 명시적 지시 없이는 하지 않는다.
- 오너가 열어둔 Unity를 강제 종료하지 않는다.
- 시크릿·토큰·쿠키·개인키를 출력하거나 외부로 보내지 않는다.
- 변경은 필요한 최소 범위로 한다.

## 문서 권위
1. 현재 사용자의 직접 지시
2. `docs/GAME_DESIGN_ASHES_TO_STARS.md`의 확정 사항
3. 관련 `GAME_SPEC_*.md`
4. 이 문서
5. 현재 코드와 실제 검증 결과

문서와 코드가 다르면 자동으로 어느 한쪽을 고치지 말고, 현재 작업과 직접 관련된 차이만 확인한다.
